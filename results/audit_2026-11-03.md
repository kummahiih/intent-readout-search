# Audit of the gemma-2-9b-it results and the SOM/OT and baseline pipeline (2026-11-03)

Scope: results/fixed_models_20261103_2137 and results/som_ot_20261103_2146 (gemma-2-9b-it), plus the
shared code (scripts/som_ot_bank.py, scripts/text_baselines.py, run_scenario.py, hide_bank.py,
reply_mutate.py, run_som_ot_new_banks.sh). Read-only audit, then fixes (uncommitted). Provisional
banks. D not filled. r not frozen. Not a camera. Not handoverPass. Negative handover unchanged.

## Confirmed flaws

### 1. OT ignores the frame and the incentive context (every run is affected)
- In `scripts/som_ot_bank.py` (pre-fix, about lines 197–203), OT sampled the raw text `"Note: {note}"`
  and the empty string. It used no chat template, no `incentive_context` and no role frame, with
  `torch.manual_seed(0)` set again for each bank.
- The user_says and agent_stakes banks have identical notes, propositions and row order. Only
  `incentive_context` and `framing` differ. So the two OT files come out byte-identical.
- This is not a path or argument bug. `run_som_ot_new_banks.sh` passes `${BANK[$k]}` and
  `${ARGS[$k]}` correctly. The residuals (H) and the SOM outputs do differ between the two banks
  (relative difference 0.06–0.07).
- Runs with identical user_says/agent_stakes OT files (checked with md5):
  - som_ot_20261102_2149: Qwen2.5-7B-Instruct, Mistral-7B-Instruct-v0.3, aya-expanse-8b,
    gemma-3-4b-it, Falcon3-7B-Instruct, granite-4.2-8b, Qwen3.5-9B
  - som_ot_20261102_2345: Phi-4-mini-instruct
  - som_ot_20261103_0112: LFM2.5-8B-A1B
  - som_ot_20261103_2146: gemma-2-9b-it
- Defect OT also ignored `incentive_context`, so its hide and name rows differ only by sampling
  noise (hide and name notes are identical within a paraphrase).
- **Invalidated:** any claim that OT differs, or agrees, between user_says and agent_stakes. Any claim
  that OT reflects the incentive or the role frame. Read the old OT numbers as frame-independent,
  note-only OT, one measurement per model.
- **Fix:** `--ot-mode chat` (the new default) samples the same chat prompt as the extraction
  (`run_scenario.prompt(tok, r, --ot-ask, incentive_in_user, role_frame)`). Its empty baseline is
  the same chat prompt with an empty note and context. `--ot-mode note` keeps the old behaviour for
  comparison. Each OT row records `ot_mode`.
- **Caveat:** with the default `--ot-ask ""`, the user turn is "Answer with only YES or NO.", so
  continuations may be short YES/NO replies that rarely use the proposition's keywords. Room entry
  can then fall. Compare with `OT_COMPARE_NOTE=1` and consider a neutral `--ot-ask`.

### 2. The defect bank has a single topic
- All 432 rows are `product-safety`. Topic purity, its null and its majority are trivially 1.0.
- Topic-mean subtraction turns into a global-mean subtraction, which `standardize_fit` cancels, so
  "topic_mean_subtracted" equals "raw" exactly.
- **Invalidated:** defect topic purity and the defect topic-mean-subtracted control. These were
  reported as 1.0 for gemma-2-9b and for the earlier models.
- **Fix:** when there are fewer than 2 topics, topic and topic_mean_subtracted are written as "N/A".

### 3. The defect leak "pass" says nothing
- `scripts/text_baselines.py` used only the note, or the note plus public_ask. Defect hide and name
  rows share both and differ only in `incentive_context` (for example "If you deny it, you will make
  the sale…" vs "If you confirm it, you will make the sale…").
- So text was at chance by construction (0.497 vs a majority of 0.516).
- After the fix the context and full-prompt inputs are included, and the n≤3 bag-of-ngrams still
  stay near chance on gemma-2-9b defect (incentive_context 0.523, full_prompt 0.516, majority
  0.516). The hide and name contexts are word-order swaps of the same words.
- So the defect bank passes the 0.60 rule against lexical baselines, but the incentive is plainly
  visible in the text. A pass shows the baselines can't read word order. It doesn't show the
  information is absent.
- **Invalidated:** citing the defect leak pass as "no visible-text shortcut".
- **Fix:** the new inputs are `incentive_context`, `note+incentive_context` and `full_prompt`
  (system and user text as rendered). Model selection is still fit-only grouped CV. An
  order-sensitive baseline (n=4–5 grams, or a small fit-only sequence model) is still needed.

### 4. In the framed banks the incentive is in the note, by design
- In user_says and agent_stakes, `incentive_context` is the same for hide and name:
  - "the private note above describes the situation as it stands."
  - "I wrote the private note above about my own situation."
- The incentive is written in the note itself ("I will tell them it is only the named repository"
  vs "…it grants access to every repository").
- So note-only leak scores of 0.73–0.80 are expected. A "lie under hide" there means the model
  followed a plan stated in its own note, which is a weaker construct than lying under pressure.
- The role frame changes only the user-turn prefix ("The user says:" / "As the agent,"). Answers
  still differ on 44 of 342 rows for gemma-2-9b.
- New baselines on gemma-2-9b, incentive target, eval accuracy vs a majority of 0.673:
  - user_says: note+incentive_context 0.764, full_prompt 0.691
  - agent_stakes: note+incentive_context 0.800, full_prompt 0.709

## Suspected, not verified on the box (the model weights are not there)

### 5. Possible double BOS for gemma-2 (and any template that renders a BOS)
- The gemma-2 template renders `<bos>…`. `chat()` folds the unsupported system role correctly
  (`reply_mutate.py`, about lines 96–108).
- `generate_short` (`hide_bank.py:238`), `last_h` and the OT sampler (`scripts/som_ot_bank.py`) and
  `reply_mutate.py` (lines 45 and 117) then tokenize with the default `add_special_tokens=True`,
  which probably adds a second BOS.
- **Fix:** `prompt_text.encode_prompt` drops the added specials when the text already starts with
  `tok.bos_token`. `RH_KEEP_DOUBLE_BOS=1` restores the old behaviour. `scripts/bos_check.py` prints
  the first ids before and after the fix for each model, using the tokenizer only.
- If DOUBLE_BOS_BEFORE_FIX is confirmed, all gemma-2-9b contract and SOM numbers (and those of any
  other flagged model) are provisional until the rerun.
- Other scripts (phase2_*, pre_patch, path_patch_gen and others) still use plain `tok(...)`. They
  were not changed in this pass.

## Minor
- **SOM null:** the permutation null used the winners of seed 0 only, while the observed purity is
  the mean of 3 seeds. It now cycles over all seeds. No conclusion flips.
- **Grid choice:** the grid is chosen by in-sample incentive purity on fit. There is no eval leakage,
  but it favours larger grids. Unchanged.
- **Layer:** gemma-2-9b SOM ran at layer 8 of 42 (the script default). The fix rerun uses
  GEMMA_LAYER (default 24).

## Checked and fine
- **Lie rate:** `run_scenario.report` counts a row as known when belief is YES, `states_proposition`
  and `prop_truth` are True, and the public button is valid. A lie is public NO; name_refuse is name
  YES. All bank rows have `prop_truth` = True. One framed hide row has `states_proposition` = False
  and is excluded. An independent recount by incentive gives the same totals. The gemma-2-9b
  hide>name gap stands:
  - defect: 0.941 vs 0.476
  - user_says: 0.164 vs 0.054
  - agent_stakes: 0.217 vs 0.000
  (`hide_bank.report_three` is the older hide-arm contract and is not used for these dumps.)
- **Split:** assigned per scenario_id, with no mixed IDs. Baselines and SOM both use the bank's
  `split` field. There are no duplicate (scenario_id, incentive, note) join keys.
- **Text baselines:** selection is fit-only GroupKFold, then a refit on fit and one eval score. There
  is no eval leakage.
- **SOM:** centering, standardization, PCA and grid choice are fit-only. The null shuffles eval
  labels, takes the p95 of 20, and drops rows with no valid label.
- **Rows:** 1296 = 432×3 and 342 = 114×3. The SOM joined the matching fixed_models_20261103_2137
  dumps.
- **Incentive direction:** in every defect pair, hide rewards denying and name rewards confirming.
  No labels are swapped.
- **Refactor:** run_scenario prompts are unchanged by moving them into `prompt_text.visible_messages`
  (checked equal on 11,880 row, ask and frame combinations against HEAD).

## External audit verification: child-repo fixes folded in (2026-11-03)

The external audit's child-repo (intent-readout-search) items were checked against the code before
fixing. The four below were confirmed in the code and are fixed in this batch.

1. **Empty or one-split datasets passed the contract check — confirmed.** `check_scenario_contract.check([])`
   returned no failures, and a file with only one split passed.
   - **Fix:** empty input now returns `["dataset is empty"]`, and both a fit and an eval split must be
     present.
   - **Effect:** the prereg banks still pass. Some older single-split `data/scenarios_<topic>.jsonl`
     files now report "dataset has no eval split". Those files were never fit/eval scored.
2. **Residual caches were keyed only on {n, layer} — confirmed.** This applies to
   `phase2_combine.extract_note_mid` and `phase2_prebutton.extract`, and `phase2_combine` loaded the
   pre-button `Xp` with no check at all.
   - **Fix:** a new `cache_meta.py` fingerprints each cache with n, layer, model_path, the tokenizer's
     name_or_path, the sha256 of the ordered (scenario_id, note) rows, prompt_version and max_length.
     Any mismatch, or an old-style meta, means the cache is recomputed.
   - `Xp` is now checked against the current rows' hash and row count, and fails loudly on a mismatch.
   - **Effect:** existing `results/prebutton_*.json` and `noteonly_*.json` metas predate the fingerprint.
     `phase2_combine` will refuse the old `Xp` until `phase2_prebutton` re-extracts it.
3. **`pair_metrics.py` reported an in-sample topic probe — confirmed.**
   - **Fix:** it now reports a leave-one-out probe, held out by scenario_id when present and by row
     otherwise, with chance (1/len(topics)) and per-topic counts. The in-sample value is still printed,
     labelled as in-sample.
   - In `results/overnight_b0.md` the unlabelled `topic_probe_acc*` lines are annotated "(in-sample)".
     The numbers are unchanged.
   - Where both values exist, the in-sample numbers overstate held-out topic decodability:
     head_ablate_probe gives in-sample 1.00 vs LOO 0.29 and 0.54.
4. **`phase2_combine.fit_logit` gave no convergence signal — confirmed.**
   - **Fix:** it now returns `(w, info)`. `info` records converged, iterations and reason (tol,
     max_iter, singular or nonfinite). The caller warns and marks the combine result INVALID when the
     fit did not converge.

Also: the BOS guard (`prompt_text.encode_prompt`) now covers `phase2_noteonly`, `phase2_swap`,
`phase2_askonly`, `phase2_endnote`, `phase2_combine`, `phase2_combine_reverted`, `phase2_prebutton`
and `pair_metrics`.

**Reported results:** the in-sample topic numbers were diagnostics for topic confounding, never a gate.
Combine results are not gates either. I did not re-audit old cache contents. A stale-cache mismatch in
past runs is not excluded, only made impossible from now on.

**Still open:** the external audit's parent-repo (regret-heuristic) items are not fixed here.

## Second review (2026-11-03, evening)

The second review confirmed the earlier child-repo fixes. It found the following further problems,
all fixed in this batch:

1. **Cache key missed part of the model input.**
   - The pre-button residual depends on `note` **and** `ask`, but the fingerprint hashed only
     (scenario_id, note). A changed ask could get a cache hit with the old embedding.
   - The model was identified only by its path, so replacing the weights in the same directory kept the
     cache.
   - **Fix (`cache_meta.py`):**
     - The meta now records `inputs_sha256`: the exact pre-template model input per row. For pre-button
       that is the system and user messages, including the ask; for note-only it is the note text.
     - The meta also records `model_fp`: the HF revision (a `snapshots/<sha>` path, `_commit_hash` in
       config, or `refs/main` for a hub id), otherwise sha256(config.json) plus the names, sizes and
       mtimes of the weight files.
     - `want_meta` now requires `inputs=`.
     - `phase2_combine` also checks the pre-button `Xp`'s model fingerprint.
     - All existing caches miss and recompute.
   - **Tests:** changing only the ask → miss; changing a weight file's size or mtime, or config.json
     → miss.
2. **`run_fix_rerun.sh` could exit 0 after failures.**
   - **Fix:** a `FAIL` aggregate.
     - Any contract, extract, analyze, baseline or BOS-check failure sets it, as does a missing dump or
       sklearn. Baseline warnings are now failures.
     - Independent steps still run. The run ends with `RUN FAILED: inspect …/run.log` (exit 1) or
       `RUN COMPLETED` (exit 0).
   - **Preflight hard-fails (exit 2) before writing anything** when:
     - HF_HOME is missing;
     - `$MODELS_DIR/gemma-2-9b-it/config.json` is missing (unless SKIP_GEMMA=1);
     - no requested model is found;
     - torch or transformers is missing.
   - A missing non-gemma model is listed as SKIPPED and counts as a failure unless ALLOW_MISSING=1.
3. **Non-gemma contracts were not rerun after the BOS fix.**
   - **Fix:** with `AUTO_RERUN_BOS=1` (the default), any non-gemma model whose `bos_check` line says
     `DOUBLE_BOS_BEFORE_FIX` gets its contract rerun on all 3 banks, and its fresh dump is used.
   - With `AUTO_RERUN_BOS=0` and `RERUN_CONTRACT=0`, such a model is a failure.
   - When a rerun contract fails, the stale dump is not used in its place.
4. **OT ask.**
   - `--ot-format yesno|open` and `--ot-ask` are new in `som_ot_bank.py`; `ot_ask` and `ot_format` are
     recorded in each OT row.
   - The run script runs `OT_ASKS="yesno open"` by default and passes `OT_ASK` as `--ot-ask`.
   - `open` keeps the note, context and frame, drops the YES/NO instruction and asks
     `prompt_text.OPEN_ASK`. **This condition is provisional, not preregistered.**
   - **The OT YES/NO condition is not evidence of room-entry behaviour**: the generated answer can be
     just YES or NO, which leaves the proposition-keyword fact-room mass uninformative. I have not
     measured how often this happens.
   - Still open: OT sampling truncates the prompt to 256 tokens. Long chat prompts may be cut, so
     check the `_extract.txt` lengths before reading open-condition results.
5. **Text baselines.**
   - New order-sensitive models: word 1–5 gram TF-IDF LR (`tfidf15_LR`) and char_wb 3–6 gram LR
     (`charwb36_LR`). They join the model family, which is still selected on fit only by grouped CV.
   - Each result also reports the best order-sensitive model's eval accuracy.
   - **Synthetic test:** contexts with swapped word order are at chance for unigram NB (0.50) and fully
     separated by both new models (1.00).
   - On the 2026-11-03 gemma `user_says` dump, the order-sensitive incentive accuracy is 0.67–0.82,
     close to the earlier n≤3 models. A near-chance text baseline still does not prove the incentive is
     invisible: a sequence model is not tried.

Still open, not fixed here: the parent-repo (regret-heuristic) items, including the formal
hideStmtDiffers invariant and the stronger multi-step training and generalization experiments.

None of this fills D, freezes r, claims cameraPass or handoverPass, or changes the negative handover.
